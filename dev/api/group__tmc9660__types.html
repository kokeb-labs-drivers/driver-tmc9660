◆ TmclLayout

enum class tmc9660::TmclLayout : uint8_t
strong

Where the type and the motor or bank bytes of a TMCL frame put their bits (ambiguity A2).

The parameter manual numbers the UART bits least significant bit first (the sync bit is bit 0): type bits 16 to 27, motor or bank bits 28 to 31, so the fourth byte reads motor << 4 | type[11:8] (MotorHigh). A vendor example is reported to pack it the other way (TypeHigh). The SPI table (Table 3) numbers its bits most significant bit first, which read literally gives a third layout (type[11:4] in byte 1). It is not offered: a chip that uses it decodes the probe frames as types that do not exist (299 reads as 0x2B0), answers an error to both probes, and the driver refuses to start (fail closed, nothing written); supporting it needs a code change (bench item A2). The documents are not settled and nothing has run on a chip, so the driver never trusts a layout: at the start of parameter mode it probes the layouts with two read-only commands and starts only when exactly the configured one (or, for Auto, exactly one of the two) is answered. A wrong layout would put a protection parameter (256 to 288) on the wire as another parameter, for example 260 as COMMUTATION_MODE.

Enumerator
Auto 

Probe both layouts; start only when exactly one answers.

MotorHigh 

Byte 3 (SPI byte 2): motor << 4 | type[11:8]; the byte before holds type[7:0].

TypeHigh 

Byte 3 (SPI byte 2): type[11:8] << 4 | motor; the byte before holds type[7:0].
