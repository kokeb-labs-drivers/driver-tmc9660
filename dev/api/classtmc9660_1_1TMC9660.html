Detailed Description

template<AnyPort Port>
class tmc9660::TMC9660< Port >

Driver for one TMC9660 on a platform port.

Lifecycle: construct with the configuration (no I/O), then EnsureInitialized(), the one way to start (bus up, optional reset, identity check in the mode the chip is expected to be in), use, optionally Deinitialize() (the gate driver is switched off). Every call that touches the chip returns Error::NotInitialized until EnsureInitialized() has succeeded, and again after the driver has seen a reset.

The chip speaks one of three protocols (Mode); a call that belongs to another mode returns Error::WrongMode and sends nothing. Every call validates its arguments against the datasheet tables before it sends a byte (Error::InvalidArgument, nothing sent).

Optional port hooks, found at compile time:

  • void DelayUs(uint32_t us) noexcept: the SPI reply gap, reset and boot waits. Without it: compile error, the waits are required.
  • bool GpioSet(CtrlPin, GpioSignal) noexcept: RSTN (hardware reset), DRV_EN, WAKE. Without it: no hardware reset, and EnableDrive() assumes DRV_EN is wired high.
  • bool GpioGet(CtrlPin, bool& high) noexcept: FAULTN, for boot completion and Service(). Without it: boot completion is waited for by time.
  • void Log(LogLevel, const char* message) noexcept: one line per lifecycle event or failure. Without it: nothing is logged.

A hook declared with the wrong signature is a compile error.

◆ BlWriteConfig()

template<AnyPort Port>
Result< void > tmc9660::TMC9660< Port >::BlWriteConfig ( const BootConfig &  config,
const BlWriteOptions &  options = {} 
)
noexcept

Write a configuration and verify it.

Refused before anything is written when config.CheckStart() fails (the application would start with a reserved BOOT_MODE or a clock other than 40 MHz) or when the LDO word changes without options.allow_ldo_change. Only the words that differ are written; the clock word with one 32-bit write; the BOOT_MODE word last. A write of the BOOT_MODE word with START_MOTOR_CTRL set starts the application (A24): the driver switches to the new mode and waits up to Config::boot_timeout_ms for its chip ID. If the start write fails other than by a bootloader error status, the start is followed all the same. End states on failure: the application is adopted (Ok); the bootloader still answers, so the driver stays in it, initialised, and returns the error; or the driver is left uninitialised in the application's mode, so a stop reaches it.

Parameters
configThe configuration.
optionsPermissions for changes that affect the board.
Returns
Ok, Refused, VerifyFailed, Timeout, DeviceIdMismatch, the bus errors.

◆ DisableDrive()

template<AnyPort Port>
Result< void > tmc9660::TMC9660< Port >::DisableDrive ( )
noexcept

Switch the gate driver off. Never refused: whatever the mode, state or earlier error, every step is attempted, the DRV_EN pin first.

Parameter mode writes COMMUTATION_MODE = 0, once more after any failure (a reported reset, a lost frame, a stale or late UART reply; the repeat resynchronises the line first), and without a DRV_EN hook then makes sure IDLE_MOTOR_PWM_BEHAVIOR is 1; register mode writes zero to MCC_GDRV_HW and MCC_PWM_CONFIG, always both, and reads both back: VerifyFailed when an energising bit is still set (a stop the chip did not apply, for example under the wrong register SPI layout, A3). In bootloader mode nothing needs switching off: with a DRV_EN hook the pin drop is the stop; without one the stop is Ok only when the bootloader still answers its chip type. BUSY, an error status or a seen reset are the bootloader answering: the error is returned, no application stop is sent and the mode stays. Any other failure may be an unseen restart into an application: the driver sends the stop of the application that BOOT_MODE names (read at adoption, before anything was written, so it is the OTP value; or by the last BlReadConfig()), else of Config::mode, becomes uninitialised in that protocol and returns the error; with no proved protocol and no hook it is NotInitialized.

Returns
The first error met; Ok when every step worked.

◆ EnableDrive()

template<AnyPort Port>
Result< void > tmc9660::TMC9660< Port >::EnableDrive ( uint8_t  commutation_mode)
noexcept

Energise the gate driver in parameter mode, after the start-up guards.

Guards, in order, all before DRV_EN or COMMUTATION_MODE is touched: mode is Parameter, commutation_mode is 1 to 8, GENERAL_ERROR_FLAGS and GDRV_ERROR_FLAGS read zero. Then DRV_EN is asserted (when the port drives it) and COMMUTATION_MODE written; if that write fails (the chip may still have run it) the full stop of DisableDrive() follows, so a failed call leaves the drive stopped also without a DRV_EN hook.

Parameters
commutation_modeCOMMUTATION_MODE value, 1 to 8.
Returns
Ok; InvalidArgument; NotInitialized; WrongMode; DeviceFault (a flag is latched: read and clear it); the bus errors.
