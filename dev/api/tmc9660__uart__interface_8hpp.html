Detailed Description

The UART port of the TMC9660 driver: the CRTP base, the UartPort concept and the bus requirements.

Copyright

The chip's host UART is 8N1, least significant bit first, and detects the baud rate from the sync bit of each request (standard rates from 9600 to 250000 at a 40 MHz system clock; up to 5 Mbit/s when the rate is configured). Derive from tmc9660::UartInterface<Self> and implement:

  • bool EnsureInitialized() noexcept: bring the UART up on the first call; true at once afterwards.
  • BusStatus Exchange(const uint8_t* tx, std::size_t tx_len, uint8_t* rx, std::size_t rx_len, uint32_t timeout_us) noexcept: send tx_len bytes without gaps between bytes, then receive exactly rx_len bytes (0 when no reply is expected). The port discards stale received bytes before it sends and removes the echo of its own bytes on a shared wire, and handles transceiver direction. A call with tx_len == 0 sends nothing: it only discards what is waiting on the line, reading up to rx_len bytes within timeout_us (the driver does this to drain a late reply after a failed exchange).
  • void DelayUs(uint32_t us) noexcept: wait (required: a port without it does not compile).

Two documents disagree on how long a gap inside a request may be before the chip discards the partial message (about 100 ms in one chapter, 10 ms in another, ambiguity A6): a port sends each request without gaps, so the question does not arise.
