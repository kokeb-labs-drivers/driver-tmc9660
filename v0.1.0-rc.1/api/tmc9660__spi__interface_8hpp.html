Detailed Description

The SPI port of the TMC9660 driver: the CRTP base, the SpiPort concept and the bus requirements.

Copyright
Copyright (c) 2026 The driver-tmc9660 authors. SPDX-License-Identifier: MIT

The driver never calls an SDK. It calls hooks on a class you derive from tmc9660::SpiInterface<Self>:

  • bool EnsureInitialized() noexcept: bring the bus up on the first call; true at once afterwards.
  • bool Transfer(const uint8_t* tx, uint8_t* rx, std::size_t len) noexcept: one full-duplex transfer, CS low for all len bytes, mode 3, MSB first; rx is always given.
  • void DelayUs(uint32_t us) noexcept: wait; used for the reply gap and the boot wait (required: a port without it does not compile).

The same SPI port carries the bootloader (5-byte datagrams), parameter mode (8 bytes) and register mode (6 bytes): the port moves raw bytes, never retries, never interprets a frame. What the chip needs from the bus is below as constexpr values (datasheet "SPI Interface", electrical characteristics); a port checks its settings against them with static_assert. The optional hooks (GpioSet, GpioGet, SckHz, Log) are described in tmc9660.hpp.
