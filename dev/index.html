Smart gate driver with servo controller

TMC9660 Driver¶

A C++20 driver for the TMC9660 servo controller and gate driver: the bootloader, parameter mode and register mode, over SPI or UART, with guards so that nothing energises a motor by accident. It runs on any MCU.

Quickstart API guide Source on GitHub

The TMC9660 is a gate driver and motor controller for BLDC, PMSM, stepper and brushed DC motors: field-oriented control, the servo loops and a ramp generator run in hardware, and a buck converter powers the chip from the motor supply (General Description, p. 1).

Quick start¶

Wire the chip as above, write the port (Porting), then read a parameter:

#include "tmc9660.hpp"

int read_actual_velocity(MyPort& port, int32_t& velocity) {
  tmc9660::Config config{};
  config.mode =
      tmc9660::Mode::Parameter; // the chip boots into the mode its boot configuration says
  tmc9660::TMC9660<MyPort> chip(port, config); // no I/O yet

  if (auto r = chip.EnsureInitialized(); !r) { // 1. bus up, identity check, first handshake
    return static_cast<int>(r.error); //    Bus, Timeout or DeviceIdMismatch: check wiring and mode
  }
  const auto v =
      chip.GetParam(tmc9660::Param::ACTUAL_VELOCITY); // 2. a checked read of one parameter
  if (!v) {
    return static_cast<int>(v.error); //    UnexpectedReset: the chip restarted, start again
  }
  velocity = static_cast<int32_t>(v.value); // 3. in the unit of the parameter
  return 0;
}

From docs/hardware.yml; kokeb-docs hardware --check confirms that every API name is in inc/tmc9660.hpp, inc/tmc9660_types.hpp and every register in inc/tmc9660_params.hpp, inc/tmc9660_registers.hpp.

The driver has no platform code. You give it a small class that brings the bus up and moves bytes; it does the rest: the frames of three protocols, the checks of every reply, the parameter and register tables, and the rules that keep the power stage off until the chip and your request say otherwise.

  • Three modes in one class. Mode::Bootloader, Mode::Parameter and Mode::Register; a call that belongs to another mode returns WrongMode and sends nothing. See Bootloader, Parameter mode and Register mode.
  • Checked tables. All 289 parameters and 163 registers of the reference manuals, with access, range and coded values; a bad value is refused before a byte leaves.
  • Safe to start and to stop. EnableDrive() reads the flags and raises DRV_EN before it sets the commutation mode; DisableDrive() is never refused. See Safety.
  • Reset-aware. The driver watches each transport for evidence that the chip restarted and sends no write after it.
  • Explicit where the documents disagree. Twenty-four ambiguities (A1 to A24), most with a knob. See Ambiguities.
  • No heap, no exceptions, no RTTI. The host tests build with -fno-exceptions -fno-rtti. See Contract.
  • Tested without hardware. Host tests run the driver against an independent model of the chip, a fuzz target attacks it, and one-edit mutants of every guard must be caught. See Testing and CI.

Not yet run on a real chip

Everything is verified against a model built from the documents. The ambiguities page lists what a bench check should settle first.
